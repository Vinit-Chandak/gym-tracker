# Coaching evaluation set

Version: 2026-09-12. All cases below are synthetic. They specify model-quality review inputs and expected decisions; they are not real athletes or production jobs. Do not invent missing fields or treat these descriptions as an accepted API result.

Create disposable test athletes with the indicated facts, collect actual claimed-job contexts through `scripts/coach/workflow.ts`, and retain the contract/policy version with each result. Run the model through the configured owner cloud routine only after checking allowance and rollout access. Deterministic acceptance tests and model-quality judgments are separate. These cases have not been run against the live model as part of this branch.

For each case record the claimed input, contract/policy version, model and runtime, output, number of corrections, acceptance outcome, elapsed time and context bytes. Review feasibility, evidence/provenance, constraint preservation, workload rationale, programme stability and unsupported claims. Each dimension is pass/fail with a concrete reason; a fluent explanation does not excuse an incompatible prescription.

A model failure needs a policy/prompt or product correction and a rerun of that case. A deterministic rejection needs a corrected contract/output; do not loosen ownership, freshness, machine, measurement or frozen-workout checks to make the model pass. Keep reports and private evidence out of shared evaluation logs.
