From the repository root, with PostgreSQL running and project dependencies installed:

```powershell
npm run audit:six-months -- setup
npm run audit:six-months -- build
npm run audit:six-months -- auth    # leave running in one terminal
npm run audit:six-months -- start   # leave running in another terminal
npm run audit:six-months -- all
```

Install the two browser engines with `npx playwright install chromium webkit` if needed. The
wrapper supplies the ports, database, output directory, fixed anchor, extended personas and
realistic workout options. Set `AUDIT_DATABASE_URL`, `AUDIT_OUTPUT_DIR`, `AUDIT_PORT` and
`AUDIT_AUTH_PORT` to create a separate replay stack. For example, use database
`overload_audit_20261007_replay` and a new output directory. The local database credentials are
`postgres` / `postgres` by default and can be overridden through `AUDIT_DATABASE_URL`.

adds no duplicate history and preserves subsequent interactions. Use a fresh replay database
to restore empty persona states. The original 56-month audit commands remain available.

## Defects fixed

1. **Actions became available before navigation finished.** Coaching and programme forms cleared
   their saving state as soon as the mutation returned. A slow page response left the old screen
   with an enabled button, encouraging another click. These actions now include React navigation
   transitions in their busy state. The audit gates the real response after a successful save to
   verify this behavior.
2. **Today lost its more-options action after late completion.** Finishing an old strength slot
   while endurance was still due could leave no way to choose another workout. More options now
   remains available on completed and endurance-only days, while active-session guards remain.
   Two focused component regressions and the real three-day backfill flow cover this.
3. **The programme heading had a small tap area and crushed text.** Its link could be only 20.8px
   high, and the cycle counter consumed the row at large text. It now has a 44px minimum target,
   flexible width and a wrapping counter. All day-tile corners are also tapped in the audit.
4. **Coach setup controls were too small or broke words.** Step navigation now has the standard
   target height; day choices use four columns on narrow screens and seven when there is room.
   Back/Continue actions wrap with enough width for readable labels.
5. **Uploaded report names collapsed into a column of letters.** Report names and selection now
   occupy their own full row; download/remove actions wrap beneath them with usable targets.
   Upload, download, removal and 320px/200% text are verified together.
6. **Exercise availability overflowed a narrow phone.** The gym name and availability badge now
   wrap without pushing beyond the viewport.
7. **The strength-chart heading pushed its help action outside the screen.** The heading wraps
   at narrow widths and enlarged text.
8. **Future calendar dates failed text contrast.** The date now uses the readable secondary-ink
   token while retaining the outlined future-day treatment in both themes.
9. **A chart could overflow before its width measurement updated.** The chart SVGs now fill
   their container immediately, including the first render and text-size changes. Browser checks
   measure both exercise charts in the same task as a text-size change, before ResizeObserver
   runs, at phone and narrow widths.
10. **Leaderboard names broke into fragments at enlarged text.** The name column now reserves
    enough character width to move onto its own line before common names and usernames break.
    The same rank-list component serves exercise and Friends boards; both browser engines check
    the long-name fixture at phone and narrow widths with 200% text.
11. **A coach intake heading collapsed beside Save and exit.** At 320px and 200% text, the
    fixed-width exit action squeezed "Starting point" into a column of letters. The header
    now wraps and reserves character space for its title. The report-upload workflow checks
    both the heading and exit action at normal and enlarged text in each browser engine.

The migrated UI also changed several legitimate labels, sheet paths, chart values and input
controls. Audit scripts now exercise those controls, native validation and current layouts while
preserving database identity, isolation, unit-conversion and no-duplication assertions.
The history audit now selects every month through the real date form. Independent control
screens use fresh documents with shared cookies/preferences, checking each document before
closing it; this avoids treating abandoned prefetch streams as errors on the next screen.
Service-worker routing is isolated from server-read and control checks and remains enabled
in the food/endurance suites that test offline behavior and private-cache boundaries.
